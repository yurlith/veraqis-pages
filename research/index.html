Every report here comes from running our own engine against a corpus with known answers, and every number is reproducible from the repository. Negative results are published alongside positive ones — a measurement that cancels a project is the one that shows the gates are real.

How these are produced

The pipeline is the same one that gates our releases, not a separate marketing exercise: a deterministic corpus generator, a corruption generator with fixed seeds, the shipped engine, and a pre-registered metric with a threshold set before the run.

  • Pre-registration. The metric and its pass threshold are frozen before the measurement, so a disappointing result cannot be reinterpreted afterwards.
  • Zero false bytes is a hard gate. Every recovery layer must return nothing wrong. A method that recovers more at the cost of one wrong byte does not ship.
  • Independent verification. Evidence counts only from a verifier the solver did not target — a checksum you fitted to proves nothing. The rule.
  • Baselines are run honestly. Where a standard tool exists — unzip, gzip -t, xz -d, qpdf --check — it is run on the same input and reported as it actually performed.
  • Negative results are published. Two of the four reports above are negative. That is not a disclosure policy, it is the point.

Nothing here contains customer data. Corpora are generated locally from fixed seeds; published artefacts carry commands, versions, damage classes and outcomes — never raw file contents.
