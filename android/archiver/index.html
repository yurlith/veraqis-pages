What it does

These features are implemented and tested in the current Android build.

SCAN

Safety scan before open

A read-only scan classifies the archive — Safe, Suspicious, Blocked, Encrypted or Unsupported — before any content is opened.

"Safe" means structurally safe to extract. File contents are not checked for malware — VERAQIS Archiver is a structural safety inspector, not an antivirus.

LIST

Safe entry listing

See the entries an archive contains without extracting them. Unsafe paths — traversal, absolute, reserved names — are flagged rather than followed.

OUT

Transactional extraction

Extraction is transactional and stays inside the destination you pick. Entries that fail a safety or integrity check are not written.

OUT

Destination you choose

Output is written into the folder you select through Android's own system picker. VERAQIS Archiver does not roam your storage.

Safety limits

Structural protections that run before any entry is written.

  • Path-traversal protection. Entries that try to write outside the chosen destination are rejected.
  • Absolute-path protection. Entries carrying an absolute path are rejected.
  • Reserved-name handling. Reserved device names (e.g. CON, PRN, NUL) and other unsafe entry names are handled safely, not written literally.
  • Archive-bomb limits. Output size and compression-ratio caps stop a decompression bomb before it can exhaust storage or memory.
  • Encrypted archive detection. Encrypted archives are detected and reported — VERAQIS never decrypts, recovers passwords, or bypasses restrictions.
  • Unsupported-format detection. Unsupported formats are detected and reported honestly rather than guessed at.

Damaged archive detected

When an opened archive turns out to be damaged, Archiver can run a recovery preview.

In-app prompt "Damaged archive detected — Run recovery preview"

The preview can show the damage class, which entries were discovered, entry names where safely available, an estimated recoverable size, and VERIFIED / DAMAGED / UNKNOWN / LOST counts with specific reasons.

This is a preview, not a save. VERAQIS Archiver does not promise to save the full recovered output. See what may still be recoverable before deciding whether you need Recovery Pro.

Privacy

VERAQIS Archiver works offline. There is no account, no cloud upload, and no telemetry — not as a setting you can turn on, but as an absence of the code that would do it. Files are processed on the device and written only to the destination you select.

This claim is scoped to the current app manifest — no android.permission.INTERNET is declared as of the last audit (security model) — and is re-verified before every release, not assumed to hold forever.

What the app can access on your device

VERAQIS Archiver requests MANAGE_EXTERNAL_STORAGE ("All files access"). This is a broad permission, and we are not going to call it harmless — it lets the app's built-in file manager browse and manage storage across the device, not just a single folder you picked. It is what makes whole-device file management (browsing, creating folders, renaming, copying, moving, deleting, sharing, previewing, and archiving files anywhere on storage) possible without repeatedly re-picking a folder.

  • Requested when, not at install: Android does not allow this permission to be granted at install time. The app asks for it from the storage-connection flow, the first time you try to use whole-device file management — not automatically on launch.
  • You can decline it. If you do not grant All files access, the app falls back to Android's Storage Access Framework: you pick a single folder per session, and the app can only read and write inside that folder. Core archive inspection and extraction still work — you lose whole-device browsing, not the app.
  • Archive contents stay local either way. Whether you grant this permission or use the SAF fallback, files are processed on the device and never uploaded — this permission does not change that.
  • Android's permission grant is not a privacy guarantee by itself. Granting file access is what lets the app read those files; our claim is that the code doesn't additionally send them anywhere, verified by the absence of android.permission.INTERNET in the shipped manifest — not that the operating system enforces privacy for you.

Known limitations

  • Not a malware scanner. "Safe" means structurally safe to extract; file contents are not checked for malware.
  • No password recovery, no encryption bypass. Encrypted archives are detected and reported, not opened.
  • Does not save full recovered output. The recovery preview is informational; saving a complete recovery is Recovery Pro's job.
  • No archive creation claim. This page does not claim ZIP/7z creation; that is not part of the current tested feature set.

When Archiver isn't enough

Archiver's recovery preview tells you whether an archive is worth pursuing. For a full damaged-ZIP recovery — verified entry by entry, with a report you can check — that is VERAQIS Recovery Pro, currently in closed Android testing.

Archiver questions

What does VERAQIS Archiver do?

It opens and inspects an archive before extraction, lists entries safely, and extracts safe entries into a folder you choose.

Does it recover damaged archives?

It shows a limited recovery preview — damage class, discovered entries, estimated recoverable size — but it does not save the full recovered output. That is VERAQIS Recovery Pro.

Does VERAQIS Archiver store passwords?

No. Passwords, when supplied, are handled as transient character data and are not stored in models or logs.

Does it require an account?

No. No account, no cloud upload, no telemetry, no ads.
