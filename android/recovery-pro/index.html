A different product, not "Archiver Premium"

Recovery Pro is not planned as the same archiver without limits, not an ad-free version, and not VERAQIS Archiver with buttons unlocked. Its job is not everyday archive browsing — that is what the free VERAQIS Archiver is for. Recovery Pro's one intended job is the moment an archive stops working and you need to know, entry by entry, what can still be trusted.

Who it is for

Anyone who will be holding a ZIP that will not open, will not fully extract, or fails on one or more entries, and will need to know which files can be proven intact before deciding what to do next — once a testable build exists.

Planned recovery scope

Proposed stable ZIP recovery scope for the first commercial release, grounded in the same recovery engine already benchmarked on these damage classes:

  • Missing end-of-central-directory record
  • Damaged central directory
  • Stale central-directory offsets
  • Local-header scanning when the index cannot be trusted
  • Truncated-entry detection
  • CRC-32 verification of every recovered entry
  • False-signature rejection
  • Overlap detection between entries
  • Recovery of intact entries before and after a damaged region
  • Stored and deflated entries
  • ZIP64, where the full path is verified

This is a target scope, grounded in the engine's own benchmark record (see CLAUDE.md "Current technical baseline" — findings F-1, F-2B, F-3 and F-4 closed on the controlled corpus, zero false recoveries) — that record belongs to the underlying Rust engine, not to a working Android build. The current Android cross-product integration exposes only recover_verified_entries — full-entry recovery, verified by CRC-32 — with no deep recovery, entry selection or report export integrated into any Android app yet. See MOBILE_ARCHIVER_RECOVERY_CONTRACT.md.

How the underlying engine works today

This section describes the existing, already-benchmarked Rust engine — not a current Recovery Pro Android feature.

A working ZIP reader starts at the end, reads the central directory, and trusts it — fast for a healthy file, useless for a damaged one, because the index is what's most likely missing. The engine reads the other way round: every entry carries its own local file header next to its data, so scanning for those headers reconstructs the archive's contents without depending on the index at all. Where the central directory is damaged, it is rebuilt from what the local headers prove, never invented. Recovery Pro is designed to bring this same approach to Android once built.

VERIFIED / DAMAGED / UNKNOWN / LOST (planned)

Recovery Pro is designed so a result is only called verified when something independent of the repair confirms it — a structural fix will not get to certify its own output. This model is already proven at the engine level (see the test record); applying it inside an Android app is the planned work.

LabelWhat it meansWhat proves it
VerifiedThese are the original bytes.The entry decompressed cleanly and its stored CRC-32 matched.
DamagedThe entry exists but its contents changed.The entry decompressed, but the CRC-32 did not match.
UnknownWe cannot say either way.No surviving evidence settles it.
LostThe data is not in the file.The bytes are absent — truncated away or overwritten.

A report that says "43 verified, 2 damaged, 1 unknown" is more useful than one that says "repaired!" and leaves you to discover which files are quietly wrong.

Relationship to the free preview

The free VERAQIS Archiver includes a limited recovery preview — damage class, discovered entries, an estimated recoverable size. Recovery Pro is intended to be the next step: the target build will recover the entries the preview identified, verify each one, and write them to a destination you choose with a full report. Free tells you whether it's worth pursuing; Pro is designed to do the recovery, once it exists as a testable build.

Planned guarantees: read-only source, separate destination

Read-only source guarantee

Recovery Pro is designed so the source archive is opened read-only and never modified. A failed recovery attempt is intended to cost you nothing — the original would stay exactly as it was.

Recovery destination

Recovered output is designed to be written to a destination you choose, separate from the source. Nothing would be repaired in place.

Report format (target)

Every recovery is designed to produce a manifest, not a claim: entry names, verdicts, byte ranges, rule IDs, and before/after hashes, so the result can be checked later rather than taken on trust. The report format itself is not hypothetical — see a real, published example generated by the same underlying engine on the test record and the reports page — but no Recovery Pro Android build produces one yet.

Honest limitations

  • No testable build exists yet. There is no public APK, no closed-test programme and no Google Play listing for Recovery Pro.
  • No password recovery is planned. Encrypted archives are intended to be detected and reported, not opened.
  • No encryption bypass is planned. Recovery Pro is not designed to remove or circumvent access controls.
  • No reconstruction of bytes that are absent. If the data was truncated away or overwritten, no analysis can return it — it would be reported as lost.
  • No guarantee every damaged ZIP will be recoverable. Recovery will depend entirely on what survived.
  • No in-place modification of the source is planned. The original file would never be rewritten.
  • No malware verdict is planned. This is designed as a structural recovery tool, not an antivirus.
  • No legal or forensic certification is planned. Recovery output is not intended to be presented as court-admissible or forensically certified evidence.
  • Other formats are not part of this commercial promise. PDF, SQLite, 7z, RAR, TAR, GZIP, XZ, BZIP2, Office and other formats have experimental engine-level work in the repository, but none of it is part of Recovery Pro's planned stable scope. See the format reference for the honest per-format position.

Recovery Pro questions

Is VERAQIS Recovery Pro available now?

No. Recovery Pro is in development. There is no testable Android build, no public APK, no closed-test programme and no Google Play listing. You can register interest for future testing.

Is Recovery Pro the same app as VERAQIS Archiver with more features unlocked?

No. Recovery Pro is planned as a separate, specialised app for one workflow: recovering a damaged ZIP. It is not intended to be VERAQIS Archiver Premium or an ad-free version of the free app.

Can it recover any damaged ZIP?

There is nothing to test yet, so this can't be measured on Recovery Pro today. The design intent is that recovery depends entirely on what survived: proving what the surviving bytes support, and reporting the rest as damaged, unknown or lost — never guessing.

Will it be able to open a password-protected ZIP without the password?

No. Encrypted archives are intended to be detected and reported only. Recovery Pro is not designed to guess, derive or brute-force a password, or to bypass encryption.

What is the price?

Planned launch price: €9.99 one-time. This is a hypothesis, not a live offer; there is no checkout, no purchase and no charge, because the product is still in development.
