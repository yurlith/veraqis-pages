SQLite recovery

A database is not an archive. An archive tells you whether a file came back intact; a database has to tell you something harder — whether the rows you are reading are the current ones. This section collects everything we have measured about recovering SQLite, including the cases where the honest answer is that the question cannot be decided from the bytes you were given.

The rule this section runs on

A recovered row is emitted only when its cell, its payload bounds, its record header, its serial types and its full body all validate. Nothing partial is presented as a row, nothing inferred is labelled verified, and no rowid is ever invented for a table that does not have one.

Every fixture asserts a claim the gates can falsify, not merely a code path.

The negative control matters as much as the rest: a run over random bytes must return nothing. A recovery engine that finds rows in noise will find them in your damaged database too.

"SQLite", not "SQL server". Everything here is about the SQLite file format — the .db, .sqlite, .sqlite3 files inside phones, browsers, desktop applications and embedded devices. It is not about MySQL, PostgreSQL or SQL Server, and nothing measured here transfers to them.

What a damaged database is made of

Three files can carry the state of one database, and which of them you were handed decides what can be proven. This is the single most consequential thing to get right before recovery starts.

filewhat it holdswhat its absence costs
name.dbthe pages of the database as of the last checkpointnothing to recover from at all
name.db-walcommitted transactions not yet folded back into the databasethe latest committed state may be missing, and the file cannot say whether it is
name.db-journalpre-images from a transaction that was in flighta rollback that was owed cannot be applied or ruled out
name.db-shmthe shared index into the WAL — a cache, not datanothing; it is rebuilt from the WAL

Copying only the .db is the most common acquisition mistake, and it is silent: the result opens, reads, and looks complete.
