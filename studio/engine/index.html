    How this works

    The page loads the VERAQIS engine once — about 1 MB — and runs it in a background thread of your browser. It is the same Rust engine as the desktop and Android apps, compiled to WebAssembly, and it answers every request the same way they do: checked against the native build, 73 of 74 test requests gave identical answers, and the one difference is the honest note below about isolation.

    Your files stay on your device

    Files are read directly from your disk in pieces; nothing is uploaded and no copy is sent anywhere. The page's security policy forbids connections to any site but veraqis.tech, and veraqis.tech is static hosting that cannot receive files. Results are created in the tab's memory and reach your disk only when you press Download. Operations that must write beside their input — a signature, repair data for a folder — work on a copy in memory.

    The only thing kept between visits is the engine's history of what you analysed, in this browser's storage. Clear it under “Your history on this device”, or with Delete all local VERAQIS data.

    What “verified” means here

    The engine marks a byte, row or object verified only when an independent check proves it, and says “unknown” for the rest. Nothing is guessed to look complete. See the evidence model.

    Limits of the browser

    • The engine can use up to 4 GB of memory. Some operations read a whole file at once, so very large files may not fit; the desktop and Android apps have no such limit.
    • Each operation runs on one thread, so heavy analysis is slower than in the apps.
    • A browser has no operating-system sandbox to offer, so reports say “isolation: limits only”. The engine's own guards — against zip bombs, paths that escape the folder and links — work exactly as in the apps.
    • Results reach your disk as downloads — one file at a time, or all together as a ZIP. To protect a folder, unpack the ZIP of repair data into that same folder.

    Free, and the code is open

    Every function here is free, with no license file and no limit on use. The code of this web version — the browser adapter, the build scripts and this page — is published in the web-engine folder of the site's repository. RAR support uses UnRAR by Alexander Roshal under its own license.
