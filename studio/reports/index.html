Reports and projects

Open a report or project file that Studio exported earlier. You do not need the original archive to read it.

Imported files are treated as untrusted. A report or project is validated against the schema, rebuilt field by field, and never executed. An entry that claims to be verified without a matching checksum is downgraded on import.

What you can open here

  • A VERAQIS project file (.veraqis-project.json) exported by Studio.
  • A diagnostic report exported by Studio or by the quick ZIP checker.

You do not need the original archive. A report is a record of what was established, so it can be read later, on a different machine, by someone who never had the file.

What a report contains — and what it never contains

Reports carry entry names, sizes, offsets, compression methods, checksum results, evidence statuses and the reasons behind them. They carry no data from inside your files: no archive bytes, no decompressed content, no embedded blobs. A test asserts this on every build.

Why import is treated as hostile

A project file is just JSON, and anyone can edit one. Studio therefore rebuilds every field from scratch with type coercion and length caps rather than trusting the file's structure, and it re-checks the one rule that matters most: an entry may only be labelled Verified if its own record shows a recomputed, matching CRC-32. Anything else claiming that status is downgraded to Unknown and the change is reported to you.
