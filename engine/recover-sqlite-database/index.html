A damaged database is not a damaged archive

SQLite is in phones, browsers, desktop applications and embedded devices, and it does not checksum its own pages. PRAGMA integrity_check confirms the B-trees are structurally sound; it does not confirm the rows still say what they said. And a database is often three files — app.db, app.db-wal and sometimes a journal — so what you were handed decides what can be proven.

The engine’s SQLite semantic recovery reads the surviving pages, rebuilds the schema, and recovers rows. A row is emitted only when its cell, payload bounds, record header, serial types and full body all validate. Nothing partial is presented as a row, and no row ID is invented for a table that does not have one.

What it recovers

Schema

Tables and their declared columns, read back from the database’s own schema pages.

Verified rows

Rows from surviving table pages, each one passing every structural check before it is emitted.

WAL overlay

If you add the -wal file, committed frames are applied over the main file, so you read the newer state.

Overflow chains

Long values that spill onto overflow pages are followed and reassembled when the chain is intact.

Deleted and free-list content is off by default. Recovering it is a separate forensic opt-in in the engine, not something it does silently.

Recover a corrupted SQLite database in your browser

  1. Open the full engine.
  2. Add the damaged .db, .sqlite or .sqlite3 file — and its -wal file if you have it. Copying the database without its WAL is the most common acquisition mistake.
  3. Optionally run Analyze a file first: SQLite has 17 rules, the second-largest family after ZIP.
  4. Open Recover contents (rows, parts, objects), choose SQLite database and press Run.
  5. Download the recovered tables and the report. Only rows that passed every check are marked verified.

Questions

Can I recover a corrupted SQLite database without uploading it?

Yes. Add the file to the full engine and run “Recover contents” with SQLite database. The database is read in your browser and the results come back as downloads.

Should I include the -wal file?

Yes, if you have it. The WAL holds everything since the last checkpoint; without it the rows you recover may not be the current ones, and nothing in the main file says so.

Does it recover deleted rows?

Not by default. Deleted and free-list content is a separate forensic opt-in in the engine. The default output is the live database as far as surviving pages can prove it.

Is this “database is malformed” repair?

It is recovery rather than an in-place fix: it reads what survives and gives you the verified tables and rows. The original file is never modified.

Does it work for MySQL or SQL Server?

No. Everything here concerns the SQLite file format only.
