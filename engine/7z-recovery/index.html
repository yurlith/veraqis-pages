What 7z recovery can and cannot do

A solid 7z archive compresses many files as one continuous stream. That is why it beats ZIP on ratio — and why one flipped bit stops decoding at the damage instead of stepping over it. The engine’s 7z method is labelled limited in its own registry, and this page says exactly where the limits are.

What the engine does for 7z

Repair the signature header

If the 32-byte signature or start header at the front is corrupted (7Z_MAGIC_001) while the data is intact, the engine restores it. This is the one 7z fault where no data was touched.

List the verified inventory

7z stores a CRC-32 per file in its end header. Files whose checksum verifies are listed as verified.

Extract intact non-solid folders

Each independently compressed folder is independently recoverable.

Salvage a solid prefix

In a solid LZMA2 folder, files stored before the damage can be recovered byte-exact — measured, with false recoveries at zero.

Measured: one bit flip in a solid archive

In a real 541-file solid archive, a flip at 95% of the payload still left 501 files (92.6%) recoverable byte-exact and CRC-verified; a flip at 20% left 87. false_files = 0 in every cell. Data after the flip was not recoverable: across 15 encoder configurations, liblzma emitted no internal resync point. Read the experiment.

Recover a damaged 7z in your browser

  1. Open the full engine and add the .7z file.
  2. Run Analyze a file: 7z has three rules — signature damaged, CRC mismatch, end header beyond end of file.
  3. For a damaged signature, run Structural repair.
  4. For contents, open Recover contents and choose 7-Zip archive.

Not recoverable by the current engine

Corruption inside a solid LZMA payload (past the prefix), a truncated end header — which takes the inventory, checksums and layout with it — and encrypted headers. If a 7z matters, turn solid mode off for the parts you cannot lose, or add repair data so damage position stops mattering.

Questions

Can a corrupted 7z archive be repaired?

Partly, depending on where the damage is. A damaged signature header is repairable. Files whose CRC-32 verifies can be listed and extracted, and in a solid folder the files before the damage can be salvaged. Data after damage in a solid block cannot.

Why is 7z harder to recover than ZIP?

ZIP stores every entry twice and compresses each independently. A solid 7z states things once and compresses files as one stream, so there is no second copy to compare and no resync point after damage.

Can it open an encrypted 7z?

No. Encrypted headers remain unrecoverable by the current engine.
