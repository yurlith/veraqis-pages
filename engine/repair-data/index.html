Recovery works best when it is prepared in advance

After damage, recovery can only use what the format itself kept — and most formats keep very little. Repair data changes that. Made while a file is still healthy, a small .phxs sidecar holds Reed-Solomon parity for it. If the file is later damaged by bit rot, a bad sector or a broken copy, the engine rebuilds it byte for byte from the sidecar.

The restore either reproduces the original exactly — checked against the protected original’s hash — or stops with an error. It never writes wrong bytes. In the engine’s registry this is Shield restore: production, with exact-parity evidence.

Five functions

FunctionWhat it does
Add repair data to a fileCreates a .phxs file for one file. You choose its size as a percentage of the file (1–100%, default 10%). Keep both files together.
Protect a whole folderRepair data for every file in a folder plus a manifest, delivered as one ZIP — unpack it into the same folder. Update redoes only files that changed since last time.
Check a protected folderFinds files that changed, rotted or went missing since the folder was protected. Read-only.
Repair a protected folderRebuilds the damaged files byte for byte. Your folder is not touched; repaired files come back as downloads.
Restore from repair dataRebuilds one damaged file from its .phxs.

Protect a folder against bit rot — in your browser

  1. Open the full engine and press Add a folder.
  2. Under Protect, open Protect a whole folder, choose the repair-data size and press Run.
  3. Download the ZIP of repair data and unpack it into the same folder.
  4. Later — after a copy, a move to new storage, a few years on a disk — run Check a protected folder.
  5. If anything rotted, run Repair a protected folder and replace the damaged files with the rebuilt ones.

Choosing the size

The percentage sets how much repair data is made. More repair data can rebuild more damage and costs more space; 10% is the default. If damage exceeds what the repair data covers, restore fails with an error rather than writing a file that is almost right.

Repair data must be created while the file is healthy — a sidecar made from a damaged file faithfully protects the damage. For archives, it also removes the worst risk of solid 7z compression: with parity, the position of damage no longer decides the loss.

Why not just keep a hash?

A hash detects

A SHA-256 manifest tells you a file changed. It cannot tell you what it was.

Repair data rebuilds

Parity can reconstruct the original bytes — and the result is still checked against the original’s hash before it is accepted.

Against tampering

The sidecar is signed. For proof that a file was not deliberately changed, add an Ed25519 signature.

Questions

What is a .phxs file?

A repair-data sidecar made by the VERAQIS engine: Reed-Solomon parity for one file, signed. Keep it next to the file it protects.

How is this different from PAR2?

The idea is the same — parity files that can rebuild damaged data — but .phxs is the engine’s own format, and a restore is accepted only if it matches the original’s hash exactly.

How much damage can it repair?

It depends on the size you choose. More repair data rebuilds more damage. If the damage is beyond it, the engine returns an error rather than a partly wrong file.

Does protecting a folder upload it?

No. The engine reads the folder in your browser and gives you the repair data as a ZIP download.

Run it on your own file — free, on your device

The full engine opens the file read-only in this browser and writes results only as downloads. Nothing is uploaded, there is no account, and every function is free.
