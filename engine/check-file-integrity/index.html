Before you repair anything, find out what is wrong

A file that will not open can be damaged, truncated, renamed, encrypted or simply opened with the wrong program — and each needs different advice. The engine’s Analyze a file function reads the file read-only and answers precisely: which format the bytes say it is, every defect it finds with the evidence behind it, a health score out of 100 and an estimate of how likely recovery is.

Every finding has a stable rule ID such as ZIP_EOCD_001 (end of central directory missing) or PDF_XREF_001 (startxref points at nothing). There are 87 rules across 11 formats, each with its field, category, severity and evidence type, so a report says exactly what was checked.

How to check a file in your browser

  1. Open the full engine and wait for “Engine ready”.
  2. Drop the file onto the page or press Add files. It is read where it is; nothing is uploaded.
  3. Under Check, open Analyze a file, pick the file and press Run.
  4. Read the health score and findings. Each finding names its rule ID — look it up in the rule reference.
  5. If recovery looks possible, open Recover → Recovery assistant: it shows which methods apply to this file and runs the one you pick.

What a health score is allowed to mean

Health is not a feeling. Under the evidence model it may rise after a repair only from an exact erasure resolved against a trusted checksum, from at least 32 bits of independent checksum evidence, or from structural uniqueness that passed its gate. Guessed bytes never move it, and neither does a checksum the repair was solved against.

In the published example a truncated ZIP reported health 15/100 with ZIP_EOCD_001; the central directory was rebuilt from surviving local headers, 8,412 bytes were recovered and 0 lost. See the test record.

Identify a file by its bytes, not its name

The analysis reports what the bytes say and what the name claims as two separate answers. A RAR someone renamed to .zip and a ZIP whose first bytes were overwritten look the same to most tools; here they get opposite advice. Read how identification works.

Questions

How do I know if a file is corrupted?

Run Analyze a file. It checks the format’s own structure and checksums and lists every defect with a rule ID, a severity and the byte range involved. A file with no findings and a health of 100 passed every check the format allows.

Which formats can it analyze?

ZIP and ZIP-based formats (DOCX, XLSX, PPTX, JAR, APK), TAR, GZIP, bzip2, xz, ISO 9660, SQLite, PDF, 7z and RAR detection, plus generic truncation, bit-flip and safety checks for any container.

Can I check a file against a known hash?

Yes. Verify integrity hashes the file with SHA-256 or SHA3-512 and checks it against a manifest if you provide one.

Does a passing CRC prove the file is unchanged?

Against accidental damage, yes to about one in four billion. Against deliberate tampering, no: CRC-32 can be forged by construction. Use a SHA-256 manifest or a signature for that — see CRC-32 collisions that pass gzip -t.
