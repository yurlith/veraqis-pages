Most “corrupted” archives have a broken index, not broken data

Archive formats keep their bookkeeping — the ZIP central directory, the TAR end marker, the ISO volume descriptor, the SQLite header — in a few small places. Damage there makes every ordinary tool refuse the file while the data itself is untouched. Structural repair rebuilds that bookkeeping from what survives and writes a repaired copy, checked byte for byte, with a signed repair manifest that records what changed and why.

Your original is opened read-only and never edited. The repaired file is a new download.

Formats and what gets repaired

The engine’s registry lists automatic structural repair as production for ZIP, OPC, TAR, GZIP, ISO and SQLite; the 7z signature repair belongs to its limited 7z method.

Three functions, one workflow

1. Repair plan (dry look)

Repair plan lists the rule-keyed repairs the engine would make and how risky each one is — without writing anything.

2. Structural repair

Structural repair performs them. Leave the strategy empty and the engine chooses (for example zip-rebuild). Aggressive also tries less certain repairs; dry run plans and checks without writing.

3. Reconcile duplicate records

Reconciliation uses the copies a format keeps of its own records — ZIP’s local header versus its central directory, ISO’s duplicated descriptors and path tables — and fixes a field only where at least two independent copies agree.

Or let the assistant choose

The Recovery assistant checks the file, shows which recovery methods apply and runs the one you pick.

Repair a corrupted ZIP in your browser

  1. Open the full engine and add the damaged archive.
  2. Run Repair plan to see what would change. Nothing is written.
  3. Run Structural repair. Leave Aggressive off for the first attempt.
  4. Download the repaired copy and its repair manifest. Keep the original until you have checked the result.
  5. Open the repaired archive, or run Analyze a file on it: every entry that passed its CRC-32 is verified; anything else stays labelled.

What the result proves

What the engine proves

  • Every repaired byte is checked against the format’s own checksum or parser, independent of the repair.
  • Each ZIP entry is verified against its own CRC-32 after the rebuild.
  • A signed repair manifest records exactly what was changed, and why.
  • Where nothing can be proven, the engine abstains and says why.

What it will not claim

  • It does not guess the contents of a damaged entry.
  • It does not mark an entry recovered because the archive now opens.
  • It does not decrypt or bypass encryption.
  • It does not claim more than the surviving bytes support.

Exact-copy reconstruction (experimental)

If you still own an earlier copy of the same file — a backup, an older version — the experimental Rebuild from your own earlier copy function copies damaged regions back from it, only where the bytes match exactly and a checksum independent of the search confirms the placement. It is same-owner only and never searches anyone else’s data. It is hidden until you tick Show experimental methods on the engine page.

Questions

Can I repair a corrupted ZIP online without uploading it?

Yes. The full engine runs in your browser tab. It reads the ZIP from your disk, rebuilds the central directory from surviving local headers and gives you the repaired copy as a download. Nothing is sent anywhere.

Will every file in the archive come back?

Only those the surviving bytes can prove. Each entry is checked against its own CRC-32; entries that fail stay labelled damaged, and entries past a truncation point are gone.

What is the repair manifest?

A sidecar file written with every repair. It records which repairs were made, why, and to which byte ranges, and it is signed so the record cannot be quietly changed.

What does “aggressive” do?

It allows repairs that are less certain. Results are still labelled by the evidence behind them; aggressive mode never turns a guess into a verified result.

Does it work on 7z and RAR?

7z gets signature and start-header repair plus limited content recovery. RAR is handled by RAR support.

The full engine opens the file read-only in this browser and writes results only as downloads. Nothing is uploaded, there is no account, and every function is free.
