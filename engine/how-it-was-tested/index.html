How the browser engine was tested

Before the full engine went live in the browser it was checked against the native build request by request and file by file, against 29 reference RAR archives, and through 59 checks of the page itself. Both WebAssembly modules rebuild byte-identical.

The engine’s own gates

Behind the browser build sit the engine’s release gates: the Rust workspace test suite, cargo fmt and clippy with warnings denied, and a recovery rule that a method returning one wrong byte does not ship (false_recovered_bytes = 0). Published measurements, negative results included, are in research; the release-level record is the test record.

Questions

Is the browser engine the same as the native engine?

Yes — the same Rust code, with two documented changes for the browser (no thread pool; a ready-made policy). 73 of 74 requests gave identical answers.

Can I verify the WebAssembly myself?

Yes. Compare the SHA-256 of the files your browser loads with SOURCE.json, or rebuild them with the published scripts.

Can I run the checks in my browser?

The engine’s start-up checks, yes: Self-test. The 59-check page suite and the native comparison ran in our environment.

Run it on your own file — free, on your device

The full engine opens the file read-only in this browser and writes results only as downloads. Nothing is uploaded, there is no account, and every function is free.
