What the engine is

VERAQIS is a recovery and file-safety engine written in Rust. The same engine the VERAQIS apps use is compiled to WebAssembly and published at veraqis.tech/studio/engine/, where it runs inside your browser tab. There is no server behind it: the page downloads the engine once (2.25 MB, about 0.9 MB compressed), starts it in a background worker and hands it your files directly from your disk.

It does four kinds of work. It checks files and names every defect it finds. It recovers what the surviving bytes can prove, from damaged archives, databases, Office documents and PDFs. It protects files in advance with repair data, encryption and signatures. And it extracts safely, refusing zip bombs, path escapes and links before anything reaches your disk.

What makes it different is a single rule: a byte, row or object is reported as verified only when a check that is independent of the repair confirms it. Everything else is reported as unknown. The engine is allowed to abstain, and it does.

Your files never leave your device

Read in place

Files are mounted read-only and read in pieces (a small read-ahead cache serves the engine from 4 MiB blocks). Nothing is copied to a server, because there is none.

No connection out

The page’s Content-Security-Policy allows connections to veraqis.tech only, and veraqis.tech is static hosting that cannot receive files. eval is not allowed.

Results as downloads

Everything an operation writes stays in the tab’s memory until you press Download. Operations that must write beside their input — a signature, folder repair data — work on an in-memory copy.

One thing kept

A history of what you analysed is stored in this browser’s IndexedDB, nowhere else. Clear it on the page or with Delete all local VERAQIS data.

What “verified” means

Most recovery tools have one dial: a confidence number. VERAQIS keeps two kinds of certainty apart. Checksum evidence is counted in bits: a matching CRC-32 is worth 32 bits, a cryptographic hash over the emitted bytes 256. Structural evidence — “this row fits exactly one recovered schema” — gets no bit value, because it fails by an incomplete model rather than by collision; it is held to a zero-false record on a corpus with known answers.

Two rules do most of the work. A checksum the repair was solved against counts for nothing (the tautology rule), so a result must be confirmed by a verifier from outside that set. And false_recovered_bytes — emitted bytes that differ from the original — is a hard gate fixed at zero on every recovery layer. Read the full evidence model.

Limits of the browser version

Memory

The engine can use up to 4 GB. Some operations read a whole file at once, so very large files may not fit.

One thread

Each operation runs on a single thread, so heavy analysis is slower than in the apps.

No OS sandbox

A browser offers no operating-system sandbox, so reports say isolation: limits_only. The engine’s own guards against zip bombs, path escapes and links work exactly as in the apps.

Downloads only

Results reach your disk as downloads, one file at a time or all together as a ZIP.

Open, reproducible, checked

The browser adapter, the two-change patch to the engine, the build scripts and the page code are published under MIT or Apache-2.0 in the web-engine folder of the site’s repository. Both WebAssembly modules rebuild byte-identical from a clean copy; their SHA-256 hashes are in SOURCE.json. RAR support is UnRAR 7.23 by Alexander Roshal under its own license.

Before publication the browser build was compared with the native build request by request: 73 of 74 answers were identical, and the one difference is the honest isolation note above. The full record is on how the engine was tested.

Questions about the engine

Is the VERAQIS engine really free?

Yes. Every function on the engine page is free, including saving recovered output, with no account, no license file and no limit on use.

Does the engine upload my files?

No. The engine runs in a background worker of your browser and reads files from your disk. The page’s security policy forbids connections to any site but veraqis.tech, which only serves the page.

Which file types can it recover?

ZIP and ZIP-based formats (including DOCX, XLSX, PPTX, JAR, APK), TAR, GZIP, ISO 9660, SQLite, PDF, bzip2 and xz, with limited recovery for 7z and RAR. Support depends on the damage: a listed format is not a promise that every damaged file can be recovered.

Is it the same engine as the VERAQIS apps?

Yes — the same Rust code compiled to WebAssembly. Compared with the native build, 73 of 74 test requests gave identical answers; the difference is that the browser reports isolation: limits_only.

Can it recover a password or open an encrypted archive without the password?

No. Encrypted archives and documents are detected and reported. A traditional-ZIP or RAR archive opens only with the password you type; nothing is guessed, cracked or stored.

Does it work offline?

The page and its worker live inside the Studio service-worker scope, so once loaded they are built to keep working without a connection.
