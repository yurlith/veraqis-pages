Why a broken PDF is usually a broken index

A PDF is a set of numbered objects plus a cross-reference table saying where each one starts. When a reader says the file is damaged, the table is usually what is damaged — and the table is the one part that can be rebuilt from the file itself, because every object announces its own number (12 0 obj) right next to its content.

The engine’s PDF semantic recovery scans the objects, rebuilds the object graph and the cross-reference table, and recovers the objects reachable from the document root. “Will not open” and “content destroyed” are almost unrelated conditions, and the first is far more common.

Repair a damaged PDF in your browser

  1. Open the full engine and add the PDF.
  2. Run Analyze a file to see which rules fire.
  3. Open Recover contents, choose PDF and press Run.
  4. Download the result and the report: recovered objects are the ones reachable from the recovered document root.

Honest limits

What the engine proves

  • Rebuilds the cross-reference table from the objects themselves.
  • Recovers objects reachable from a recovered document root.
  • Works when an older xref section survives an incremental update.

What no tool can prove for PDF

  • A PDF stores no checksum over its content, so a flipped bit inside a page stream can go unnoticed — the page is quietly wrong.
  • Objects that are not reachable from the root are not labelled verified.
  • Encrypted PDFs are detected and refused.

Questions

Can I repair a PDF online without uploading it?

Yes. The engine runs in your browser, reads the PDF from your disk and returns the result as a download.

Why does my PDF say “damaged and could not be repaired”?

Usually because the cross-reference table or the startxref pointer is broken. Every object still names itself in the file, so the table can be rebuilt by scanning.

Can it repair a password-protected PDF?

No. Encrypted PDFs are detected and the engine abstains.

Will every page come back?

Pages whose objects survive and are reachable from the root come back. A PDF has no content checksum, so the engine cannot prove a page’s content is unchanged.
